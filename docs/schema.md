# diagnosis.json 数据规范（schema 1）

每个方法论文件夹里的 `diagnosis.json` 驱动网站上的概览和自诊断。网站有三种诊断模块，都是可选的，方法论用得上哪种就写哪种：

| 模块 | 字段 | 适合 | 网站上的表现 |
|---|---|---|---|
| 准入判断 | `gates` | "能不能做"的前提条件 | 每条单选，结果为 通过 / 有风险 / 不通过 |
| 阶段定位 | `stages` | 按规模、预算、生命周期分档 | 单选一档，给出该档的应做与不该做 |
| 步骤路径 | `steps` | 有先后顺序的执行步骤 | 每步若干勾选项，找出卡在第几步 |

如果一个方法论不是"有顺序的步骤"（比如一组并列的原则），`steps` 仍然可以用，但要在 `meta.steps_ordered` 设为 `false`，网站会改为显示"未完成项"，而不是"卡在第几步"。

## 顶层字段

```jsonc
{
  "schema": 1,
  "id": "baipai-to-brand",          // 与文件夹名一致，小写英文和连字符
  "title": "从白牌到品牌",
  "subtitle": "一句话说明结构",
  "summary": "两三句话的核心观点",
  "source": { "title": "", "url": "", "note": "", "transcript": "逐字稿的 GitHub 链接，可选" },
  "tags": ["品牌建设"],
  "added": "YYYY-MM-DD",
  "meta": { "steps_ordered": true },  // 可选，默认 true
  "gates": { ... },                   // 可选
  "stages": { ... },                  // 可选
  "steps": [ ... ],                   // 可选
  "caveats": ["使用时的提醒"],         // 可选
  "pitfalls": [ ... ]                 // 可选，错误打法，进入错题集
}
```

## gates

```jsonc
{
  "title": "00 准入判断",
  "tag": "路线图上这一站的副标题，可选，默认“能不能做”",
  "intro": "说明",
  "items": [
    {
      "id": "product",
      "title": "产品底子",
      "summary": "概览里显示的一句话",
      "question": "问卷里显示的问题",
      "veto": true,                 // 可选，不通过即一票否决
      "options": [
        { "label": "选项文字", "outcome": "pass | risk | fail", "advice": "选了这项给出的建议" }
      ]
    }
  ]
}
```

总结论规则：有一票否决项不通过 → 不建议做；其他项有不通过 → 补救后能做；有风险 → 能做，有风险；全部通过 → 可以做。

## stages

```jsonc
{
  "title": "所处阶段",
  "heading": "页面上阶段表的标题，可选，默认“<title>：每个规模做到哪一步”",
  "desc_label": "阶段表第二列的列名，可选，默认“规模与预算”",
  "question": "品牌现在处在哪个规模？",
  "note": "口径说明",
  "options": [
    {
      "id": "s2", "label": "② 千万级", "desc": "营收约 1000–3000 万", "budget": "年约 70–300 万（推算）",
      "expect_done": ["01", "02"],   // 这个阶段应该已经完成的步骤 id，没完成的算欠账
      "focus": "05",                  // 这个阶段的重点步骤
      "dos": ["应做"], "donts": ["不该做"]
    }
  ]
}
```

## steps

```jsonc
[
  {
    "id": "01", "title": "补基础", "tagline": "一句话",
    "points": ["概览和脑图里显示的要点"],
    "checks": ["问卷里的勾选项，全部勾上视为这一步完成"],
    "actions": ["卡在这一步时给出的动作建议"],
    "done_signal": "完成标志"
  }
]
```

## pitfalls（错题集）

每套方法论里提到的错误打法都写进 `pitfalls`，网站的错题集页面会把所有方法论的错题汇总在一起，并在诊断结果里显示卡点步骤对应的错题。

```jsonc
[
  {
    "id": "mcn-rebate",               // 本方法论内唯一，小写英文和连字符
    "category": "组织与认知",          // 必须是下面六个分类之一
    "step": "03",                     // 关联的步骤 id，准入判断用 "00"
    "title": "错误打法，用一句话描述做法本身",
    "symptom": "怎么识别：团队正在这样做时会看到什么现象",
    "why": "为什么错",
    "fix": "正确做法"
  }
]
```

分类固定为六个，新增分类前先确认现有分类确实放不下：

| 分类 | 放什么 |
|---|---|
| 产品与定位 | 产品验证、PMF、差异化、品牌宣称 |
| 品牌建设 | 主张、视觉、品牌行为、品牌心智 |
| 内容 | brief、脚本、内容形式、表达方式 |
| 达人与投放 | 达人选择、测试、铺量、头部配置 |
| 预算与 ROI | 预算分配、ROI 测算、价格带 |
| 组织与认知 | 老板思维、内外部分工 |

## pitfalls/team.json（团队复盘）

团队自己踩过的坑写在仓库根目录的 `pitfalls/team.json`，格式和上面相同，另外加两个字段：

```jsonc
{
  "pitfalls": [
    {
      "id": "2026-11-mkb-launch-discount",
      "category": "预算与 ROI",
      "project": "MKB 坐垫上市",       // 发生在哪个项目
      "date": "2026-11",               // 发生时间
      "title": "……", "symptom": "……", "why": "……", "fix": "……",
      "related": "growth-positioning:discount-volume"  // 可选，对应的方法论错题
    }
  ]
}
```
